# Repository memory

This file contains reviewed, durable rules for `voku/agent-loop`. Raw observations belong in `.agent-loop/learning/findings/`; repeatable behavior belongs in tests, dogfood runners, or static rules. A row here is deliberately short because memory is an index into executable truth, not a replacement for it.

## Durable repository rules

| Subject | Durable rule | Canonical home |
| --- | --- | --- |
| Internal package boundaries | Workflow orchestration calls focused-package typed PHP APIs when they exist. User-facing package CLI delegation stays at the Dispatcher boundary; do not reconstruct focused-package argv inside `voku\\AgentLoop\\Workflow`. | `phpstan/Rules/NoFocusedPackageCliInWorkflowRule.php` and workflow tests |
| Workflow session invariant | Governed workflow orchestration has at most one active session per task. Start/plan may reuse that session; if more than one active session already exists, fail before further task work. Retries after partial failure must not allocate another active session. | `WorkflowStartCommand`, `WorkflowPlanCommand`, and workflow tests |
| Dogfood entrypoints | Repository self-dogfood executes `php bin/agent-loop`; installed-consumer dogfood separately proves `vendor/bin/agent-loop`. They are different packaging contracts and both remain covered. | `tools/self-shape-dogfood.php` and `tools/release-set-dogfood.php` |
| Pull-request dogfood credentials | A PR self-shape job needs repository history, not write access. Keep its `GITHUB_TOKEN` at `contents: read` and use checkout with `persist-credentials: false` so PR-controlled code does not inherit a persisted repository credential. | `.github/workflows/ci.yml` and `.agent-loop/learning/findings/validated/finding.2026-08-07.007.json` |
| Self-review close-out | An exploratory blind-spot review may warn while work is open. Before close, run `recall log-outcome` and record a checkpoint that evidences both outcome close-out and `review blindspots`. `workflow close` owns the gate: it refuses a missing, invalid or `fail` report and admits a `warn`, because advisory findings such as `security_sensitive_context` fire on any diff that mentions security terms and cannot be resolved by working harder. CLI exit 0 alone is not sufficient evidence, so the residual status is recorded as close-out evidence rather than inferred from the exit code. | `WorkflowCloseCommand::checkReviewGate()`, `tests/WorkflowCloseCommandTest.php`, and `tools/self-shape-dogfood.php` |
| Tooling test isolation | Project-specific PHPStan rule fixtures run in a separate PHPStan process. Do not load `PHPStan\\Testing\\RuleTestCase` into agent-loop's normal PHPUnit process while `agent-map` also performs Composer-based PHPStan discovery there. | `phpstan/Rules/NoInProcessPhpstanRuleTestCaseRule.php` and `tools/project-phpstan-rules.php` |
| Git repository detection | Repository state is asked of Git, never inferred from the shape of `.git`. A linked worktree stores `.git` as a file, which silently turned `init doctor` and `init sync-githooks` into no-ops for a valid checkout. | `phpstan/Rules/NoGitDirectoryShapeAssumptionRule.php`, `src/GitWorkTree.php`, and `tests/GitWorkTreeDetectionTest.php` |
| CI ownership | GitHub Actions executes the repository dogfood runner; it does not duplicate the governed lifecycle or maintain a second hard-coded changed-file list. The runner derives PR scope from Git. | `tools/self-shape-dogfood.php` and `.github/workflows/ci.yml` |
| Learning decision consistency | The self-shape learning decision follows the durable evidence in the actual PR diff. If project findings or `MEMORY.md` are changed, record `findings_recorded`; otherwise record `no_durable_learning`. Do not close with a learning state that contradicts the repository evidence produced by the task. | `tools/self-shape-dogfood.php` and `.agent-loop/learning/findings/validated/finding.2026-08-07.006.json` |
| Derived state paths | A repository-local derived path has one owner for reading *and* writing. `ProjectLayout::mapSearchIndex()` was read by `workflow approve` and written by nothing, so ranked map evidence silently never reached the governed context. When a decisive-evidence channel is unavailable, the workflow says so rather than compiling a quietly narrower context. | `src/Dispatcher.php`, `tests/MapSearchIndexOwnershipTest.php`, and `tests/WorkflowApproveSearchIndexEvidenceTest.php` |
| Memory follows executable truth | When a `MEMORY.md` row and its named canonical home disagree, correct the row towards what the code enforces; do not add a second enforcement point to make the prose true. | `.agent-loop/learning/findings/validated/finding.2026-08-14.007.json` and `docs/agents/dogfood/2026-08-14-second-learning-pass.md` |
| Blind-spot review of a diff | Read a change for what it removed, not only for what it added. An invariant that held by construction needs an explicit assertion once its construction changes; a random source is injected rather than sampled by a test; a process call is not a drop-in for a filesystem check, because it can fail in ways that print. | `.agent-loop/learning/findings/consolidated/finding.2026-08-14.015.json` and `src/GitWorkTree.php` |
| Runtime dependency boundary | A package cannot be dev-only while a class `agent-loop` publishes depends on it: `ArchitectureRules` ships in `src/` and implements `ItpContext\\Contract\\RuleIdentifier`, so anything reflecting over production classes fatals without it. Loading a shipped class is not the same as running a command, so a CLI smoke test cannot decide a dependency boundary. | `tests/RealIssueEvidenceToolBoundaryTest.php` and `docs/agents/dogfood/real-issue-acceptance.md` |
| Governed context evidence conservation | When decisive evidence is missing from a governed context, first establish where it was lost along map discovery, Recall selection and context projection. Widening search, changing ranking or raising the context budget is a last resort and must be recorded in the frozen replay. | `tests/FrozenReplayEvidenceChainTest.php` and `tests/WorkflowApproveSearchIndexEvidenceTest.php` |
| Learning evidence detection | Detect learning evidence by finding identity across every findings state directory, not by the directory a finding currently occupies. A `MEMORY.md` change with no finding evidence fails the gate rather than selecting a status around it. | `tools/self-shape-dogfood.php` and its tests |
| Tool-coupled instruction assets | Machine-readable instruction assets coupled to a tool's CLI, schema or output contract ship from the repository that owns the tool and are tested with it. A general skill collection may reference or install tool-owned assets but must not keep a second canonical copy. | `resources/operating-prompts.json` and `.agent-loop/learning/findings/consolidated/finding.2026-08-14.005.json` |
| Dogfood runners are orchestration only | Runners orchestrate; every decision they make lives in a tested class under `src/Dogfood/`. Convert a shell runner for testability rather than portability - Git for Windows ships bash. A static rule carries the scope it was earned in: `-n` belongs to validation subprocesses, not to invoking our own CLI, which needs the extensions `php.ini` loads. | `src/Dogfood/SelfShapeEvidence.php` and `tests/SelfShapeEvidenceTest.php` |
| Learning promotion | Findings are evidence, not durable memory. Promote only reviewed lessons; when a rule is objectively detectable, back the memory entry with a test, dogfood gate, or static-analysis rule. | `docs/workflow/learning-boundary.md` and `.agent-loop/learning/` |
