## Executable first gate

[The task-specific CI workflow](../../.github/workflows/gh-1031-oracle-calibration.yml) checks out each immutable baseline and its historical repaired commit. It injects the **same** repaired-side regression test into the baseline, installs each checkout's locked dependencies, runs the focused test on both, and requires **baseline RED / repaired GREEN**. Raw logs, source/lock identities, selected test, and exit codes are uploaded even if the job fails.

This calibrates whether the oracle distinguishes a real defect from its repair. It proves **nothing** about an LLM's ability to produce that repair. Do not treat a synthetically failing control or a green CI job as an A/B/C win. Investigate any failure to reproduce before proceeding.

## Actual host comparison, once calibration passes

Reuse #1031's three arms, not another product mode: **A** native host, **B** native host plus only supported minimal Loop governance, **C** released default agent stack. Freeze the same host/model ID, source SHA, task wording above, tools, permission envelope, time/token budget, and acceptance oracle for all arms. Randomize/crossover order and use independent fresh worktrees. Run Codex and Claude only when a real provider and authorized execution are available; fake-provider runtime proofs are not coding-outcome evidence.

Outside the candidate workspace, grade the exact diff and independently run the oracle plus PHPStan/format and applicable security tests. Capture actual tool/CI exits, unauthorized or out-of-scope edits, unearned DONE claims, independent review defects, interventions, time and host-reported tokens (or `unknown`). Restrict task network and reference access so the historical solution does not leak into candidates. Never auto-approve B/C Contracts or ignore human Authority to make a benchmark run.

**Current evidence boundary:** the three model-run arms for every task are `NOT_RUN`; all quality and token comparisons are `UNKNOWN`. The CI gate only calibrates external oracles. Do not change the default workflow or delete mandatory components until comparable real-host outcomes exist.

## Limitations

Historical tasks may already be familiar to a model. One focused test is not proof of the entire behavior or security boundary. The cross-file and security cases also need their relevant full test suites before claiming completion. If tests cannot be injected cleanly into an older source snapshot, label that case `UNAVAILABLE` and record why instead of substituting a fabricated pass.
